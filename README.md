# 编程练习台

一个单文件、零依赖的浏览器编程练习页，目前支持 **C / C++**，结构上按「多语言」预留（语言下拉、独立缓冲、按语言切换的补全）。
可以双击本地打开，也可以直接部署到 GitHub Pages。

## 本地打开

- 双击 `index.html`（Chrome / Edge）
- 代码自动存在浏览器里，关掉再打开还在

## 上线到 GitHub Pages

和书架资料库一样用**分支部署**，不需要 Actions：

1. 新建仓库（建议名 `cpp-lab`），把本目录里的**内容**上传到仓库根目录，不要把 `cpp-lab` 这一层套进去
2. 仓库 **Settings → Pages → Build and deployment → Source** 选 **Deploy from a branch**
3. Branch 选 `main`、目录选 `/ (root)`，点 **Save**
4. 等 1～2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`

根目录的 `.nojekyll` 会让 Pages 跳过 Jekyll 原样发布，别删。

自定义域名：根目录新建 `CNAME`（内容只写域名），DNS 加一条 CNAME 指向 `<用户名>.github.io`，Cloudflare 保持灰云。

两点注意：

- 线上和本地是两套 `localStorage`，代码不会自动同步
- 「运行（联网）」需要浏览器能访问 `ce.judge0.com`

## 编辑体验（和 IDE 对齐的部分）

- 输入左括号 / 引号自动补右边，光标停在中间
- 有选区时输入左括号，会把整段包起来，例如选中 `abc` 打 `(` 得到 `(abc)`
- 输入右括号时，如果正好是自动补的那个，直接跳过，不会重复补一个
- 空的一对 `()` `[]` `{}` 中间按退格，一次删掉两个
- 空的 `{}` 中间按回车，展开成三行并自动缩进
- **在注释、字符串里打字不会自动补括号**，避免添乱
- 关掉了字体连字：`Cascadia Code`、`JetBrains Mono` 这类字体会把 `!=` 画成 `≠`，这里按源码原样显示，编辑器**不会自动改你的代码**
- `Ctrl + /` 对选中的多行整块加 `// ` 或去掉 `// `
- 行内输入 `#include` 加空格后，直接弹出头文件列表；继续打字会按前缀过滤
- 顶部切换 **C / C++** 时，代码、问题列表、补全范围一起切：两种语言各存一份缓冲，互不覆盖；状态栏会显示当前语言
- 第一次切到另一种语言时，会载入该语言的默认模板（`#include` + `main` + `return 0` 的最小骨架）
- 载入时会去掉末尾多余的换行，编辑区不会多显示一行空行
- 之后再切回来就是你自己的代码
- C 模式下 `#include` 补全只列 C 头文件，C++ 模式下 C 和 C++ 的都列
- 从旧版本升级（只有一份代码）时，第一次打开会自动迁移到当前语言，不会丢
- 拖动编辑器与右侧面板之间的分隔线可以调整宽度，双击恢复 360px，宽度记在本地
- 窗口窄于 820px（比如竖屏或分屏）时，布局自动变成上下排列，分隔线变横向、拖动调整编辑器与面板的高度，双击恢复 42%，高度单独记住；工具栏也会自动换行
- 「打开」按文件后缀自动切语言：`.c` → C，`.cpp` / `.cc` / `.cxx` / `.h` / `.hpp` → C++；未知后缀保持当前语言
- 读取文件时自动识别 UTF-8 / GBK，去掉 BOM 和末尾空行；打开前会先保存当前语言的代码，再覆盖目标语言的缓冲
- 也可以直接把代码文件拖进编辑区
- 点「重置」把当前语言的代码恢复成基本骨架，问题列表同步清空

函数名的着色规则：标识符后面紧跟 `(` 就按函数处理（跳过 `if`、`for`、`sizeof` 这类关键字），所以声明、调用、类方法调用都会着色。

语法配色只有一套 VS 风格，明暗由右上角 ◐ 切换：

| | 关键字 | 类型 | 类型名 | 函数 | 变量 | 字符串 | 数字 | 注释 | 预处理 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 浅色 | `#0000FF` | `#2B91AF` | `#2B91AF` | `#795E26` | `#001080` | `#A31515` | `#098658` | `#008000` | `#808080` |
| 深色 | `#C586C0` | `#569CD6` | `#4EC9B0` | `#DCDCAA` | `#9CDCFE` | `#D69D85` | `#B5CEA8` | `#57A64A` | `#9B9B9B` |

「类型名」指 `struct Score` 里 `Score` 这种跟在 `struct` / `union` / `enum` / `class` 后面的名字，用青绿 `#4EC9B0` 模拟 VS 的语义着色；预处理指令（`#include` / `#define`）用灰色，和 VS 一致；普通文本深色是 `#D4D4D4`。

## 检查哪些问题

| 检查 | 级别 | 例子 |
| --- | --- | --- |
| 括号配对 | 错误 | `int main() {` 少了 `}` |
| 字符串 / 字符常量闭合 | 错误 | `printf("hi);` |
| 块注释闭合 | 错误 | `/* 没有结束` |
| 全角标点 | 错误 | `printf（"hi"）；` |
| Unicode 符号 | 错误 | `≠` 应写 `!=`、`≤` 应写 `<=`、`→` 应写 `->`、`−` 应写 `-`、`“”` 应写 `"` |
| `#include` 写法 | 错误 | `#include stdio.h` |
| `#if` / `#endif` 配对 | 错误 | 多了 `#endif` |
| 可能缺少分号 | 警告 | `int n = 3` 下一行直接 `printf(...)` |
| 条件里误用赋值 | 警告 | `if (n = 3)` |

两条边界：

- **注释和字符串里的全角/Unicode 符号不报**，比如 `// 这里写 ≠` 或 `"中文，标点"` 都是合法的
- 「条件里误用赋值」只看 `if` / `while` 的括号内部，`if (b & 1) r = ...;` 这种语句体里的赋值不会误报

## 检查不了哪些（重要）

这是**本地启发式检查**，不是真编译器。以下问题它发现不了：

- 类型错误：`int x = "abc";`、`double` 传给 `int` 参数
- 未声明的变量 / 函数
- 缺少 `#include` 导致的 `printf` 未定义
- 数组越界、死循环、内存问题
- C++ 重载、模板实例化错误

要拿**真正的 gcc/g++ 报错**，点「运行（联网）」。它把代码提交到 Judge0，
由对方服务器编译执行，再把编译器原文返回——那才是真正的报错。

## 运行（联网）

1. 点右上「运行（联网）」
2. 代码以 base64 提交到 `https://ce.judge0.com/submissions`，由对方用 gcc / g++ 编译
3. 「输出」标签页显示：编译输出、程序输出、标准错误、结果（Accepted / Compilation Error）、用时和内存
4. 「标准输入」框里的内容会作为 `stdin` 传给程序
5. 网络错误或 5xx 会自动重试一次；4xx 不重试

失败时页面会给出原因，常见是：

- 公共实例每天有提交次数上限，触顶会返回 429
- 浏览器访问不了 `ce.judge0.com`（网络 / 代理）
- 右下角的服务地址填错

**语法检查完全在本地，联网失败不影响它。**

服务地址可以在右下「远程编译设置」里改，填自建的 Judge0 地址即可（仍然是同一套 `/submissions` 接口）。
代码会发到对方服务器，别在里面写敏感内容。

### 内存怎么算的

运行时会自动在代码**末尾**追加一小段统计代码（不影响行号，也不改变你的逻辑）：

- 进程启动时读 `/proc/self/status` 的 `VmRSS`，记为**启动基线**
- 程序退出时读 `VmHWM`（峰值），用 stderr 上报，页面再把它从输出里过滤掉

所以结果长这样：

```text
内存峰值 9.3 MB（启动基线 1.2 MB · 程序自身 +8.2 MB）
```

几点说明：

- 空程序也会显示「程序自身 +24 KB」，那是 stdio 等运行时的真实开销，不是噪声
- 统计的是**实际驻留内存（RSS）**：`static char a[4MB]` 不写入就不会占用，写满才涨
- 程序崩溃、`abort()`、`_exit()` 或超时时，退出钩子不会执行，页面会降级成只显示 Judge0 的总量，并标注「程序自身不可用」
- 统计只在「运行（联网）」里生效；本地语法检查不涉及

## 后续可以升级的方向

1. **真 clang（WASM）**：把 clang 编译成 WebAssembly，离线也能给出编译器级报错，
   代价是首次加载 20–30 MB（含 sysroot）。要联网下载构建产物，当前环境做不了，
   可以在你本地或 GitHub Actions 里构建。
2. **tree-sitter**：比启发式检查更准（真正的 C/C++ 语法树），体积只有几百 KB，
   但仍只查语法、不查类型。
3. **Python**：加 Pyodide 就能在浏览器里跑 Python。

## 已知限制

- 单文件、单翻译单元，不支持多文件工程
- 没有调试器（断点、单步）
- 补全只覆盖 `#include` 的常用头文件，没有函数签名补全和跳转
- 中文输入法在部分浏览器下与 Tab 缩进有冲突，可先切英文再按 Tab
